Candidate 1 — Strong Recommendation
Involves: src/App.tsx, TabletOrderPanel.tsx, PaymentDock.tsx

Deepen Order Intake & Cart State into an Autonomous OrderSession Module

The Problem (Friction & Shallowness)

Order draft state is currently scattered across App.tsx: product item dictionaries, quantity mutation callbacks, line-subtotal calculations, discount deductions, validation rules, and haptics. App.tsx must pass 15+ individual props down to TabletOrderPanel and PaymentDock.

Deletion Test: If you delete the 15+ props in App.tsx, you don't delete complexity—you just scatter cart math across UI components.

The Solution & Leverage

Create a deep OrderSession module. The interface is small and high-leverage: add(id), remove(id), setDiscount(n), commit(), and summary.

Benefits: Perfect locality for pricing, validation, and discount capping. Cart logic becomes 100% testable in pure unit tests without mounting any React components or browser DOM.

Candidate 2 — Strong Recommendation
Involves: src/App.tsx, Header.tsx, types.ts

Encapsulate Offline Queue & Google Sheets Protocol in a Deep SyncEngine

The Problem (Friction & Leaking Seam)

Google Sheets Apps Script sync logic, exponential retry timers, local storage queue serialisation, and network failure fallbacks are implemented directly inside React useEffect and state variables in App.tsx.

If network connectivity drops during order submission, the retry queue is trapped inside UI component lifecycle.

The Solution & Leverage

Extract a dedicated SyncEngine with a SheetsAdapter. The interface for the UI is minimal: enqueue(order), flush(), and status: { pendingCount, isSyncing, hasError }.

Benefits: Offline storage, exponential backoff, and Sheets API format changes can be tested and verified with mock network calls completely outside React.

Candidate 3 — Worth Exploring
Involves: PaymentDock.tsx, TabletOrderPanel.tsx

Unify Media Compression & Proof-of-Payment Intake

The Problem (Duplicated Mechanics)

Both PaymentDock.tsx (for mobile view) and TabletOrderPanel.tsx (for iPad view) contain identical 25-line HTML5 Canvas image resizing algorithms, JPEG compression math (0.65 quality, max 1000px width), and file input lifecycle handlers.

The Solution & Leverage

Extract a deep compressPaymentProof(file) utility or headless usePaymentProof seam that accepts an input event or File object and produces a standardized, compressed data URL.

Benefits: Eliminates code duplication between mobile dock and tablet sidebar, centralizes memory safeguards for camera capture, and allows isolated testing of image compression bounds.

Top Recommendation

Start with Candidate 1: Deepening the Order Intake (OrderSession)

Candidate 1 offers the highest architectural leverage. By pulling cart mutations, subtotal math, and discount validation out of App.tsx into a deep OrderSession, we immediately decouple the complex tablet split layout from transaction math, eliminating 15+ prop drilling channels and making the core cashier logic 100% testable in isolation.
